# @deepseek-ai/dsh-host-pto-artifact-inspection

English | [中文](README.zh.md)

## Summary

The Remote registers only explicit user-selected directories, returns fact-only profiles and action readiness, and exposes supported HTML through unguessable exact-file routes. It never serves a source directory, executes an artifact, or infers run failure from missing files.

The profile currently opens self-contained dependency, memory-map, and IR-trace HTML. The package also owns fail-closed first-send admission and the pinned official dependency-redundancy tool bridge for a qualified official Skill.

## Model Experience

### PTO artifact analysis

#### What the model sees

The composed tool catalog includes `pto_dependency_redundancy` with record-id and record-revision inputs. On an admitted first user step, the model also receives one structured PTO analysis context message and the exact provider-qualified official Skill instructions. A successful tool call returns both required reduction modes, bounded stderr/cycle facts, output references, the immutable admission receipt, and explicit limitations.

#### Token effect

The fixed tool schema contributes to requests where this tool is available. The analysis context and official Skill body are added only after the user explicitly stages and sends an admitted analysis draft; viewer-only requests add no model tokens.

#### KV Cache effect

The fixed tool schema is stable for one deployment. Record revision, artifact references, receipt identity, and Skill instructions are request-specific tail content, so starting or changing an admitted analysis changes that request context without mutating the deployment-owned prefix.

## Known Limitations and Deferred Work

The admitted qualified Skill owns analysis instructions. The PTO pre-step listener runs around canonical Skill injection, checks matching names against the admitted provider and rendered body, and emits one instructions message. A conflicting provider or changed body rejects the step. Existing analysis context prevents repeat injection on retries. This coordination does not change the admission receipt or tool gate.

<a id="known-limitations-and-deferred-work"></a>

- Generated or service-backed timeline, critical-path, and program-graph viewers are not installed.
- Static viewers are view-only and expose no selection or deep-link callback.
- Dependency analysis requires the configured Python executable, pinned tool path, live Session Agent, and exact qualified Skill provider.
- Tool outputs are retained in the configured app-owned directory; this package does not yet publish a cleanup or retention policy UI.

No invariant companion is published because records, viewer routes, and admissions are private lifecycle-owned maps with no independent diagnostic projection.
