# Agent Note: Run Records sidebar information architecture

Status: implemented

[English](2026-08-24-run-records-sidebar.md) | 中文

## Problem

浏览区域的第二个 Tab 以 Run History 之名预留了导航与搜索外壳，却没有模型、没有行，也没有任何东西能进入其中。这个名字也与 PTO 工作台设计对该对象采用的术语（运行记录 / run record）不一致。运行记录是一个装着构建与运行产物、供操作者回溯的目录；工作台需要把它列在会话旁边，但不能让它冒充任务起点，也不能带上会话树的排序与分组动词——脱离工程的 run 列表回答不了这些维度。

## Decision

该 Tab 是**运行记录**，其面板是会话树的结构孪生：按 Host 顺序为每个已注册 Workspace 各一节，其后是 Ungrouped。其余一切都刻意更少。区头只有搜索——没有新会话、没有视图选项、没有分组方式。行没有排序、没有拖拽、也没有点击目标：卡片操作集（查看产物、打开报告看板、新建会话）是另一项设计，在它成型之前，行不得承诺一个它并不执行的跳转。折叠栏完全不承载运行记录，因此收起侧边栏会让该区域回到会话，并连同运行记录查询一起丢弃，而不是让它去过滤会话。

这里的 Ungrouped 是**导入桶**，不是会话树的溢出桶。它在为空时也照常渲染，因为打开 run 目录的尾部 hover 显现 `＋` 只挂在该行上，别处都没有；隐藏空桶就等于隐藏这个列表唯一的入口。工程分节没有 `＋`——其下的 run 由扫描得到，不能手工添加——也没有 Workspace 重命名／删除菜单，那属于持有注册记录的会话 Tab。

打开一个 run 目录只登记一条浏览器持久化记录，不创建 Workspace；注册延迟到在该记录上开出第一个会话时，因此看过一次即弃的目录不会进入会话 Tab 的工作区列表。分组归属在**打开那一刻一次性判定**：命中包含该路径的最内层已注册 Workspace，否则进入导入桶。此后归属是黏性的。之后再注册父工程不会移动这条记录，父工程自身的扫描会把同一目录作为它自己的行呈现——同一个目录两张行，这是有意为之，因为从两者开出的会话 cwd 不同，agent 可写的范围也就不同。

移除一条记录只是摘掉登记，既不动目录也不动其中的文件，与删除 Workspace 注册记录是同一条保留边界，因此确认方式也相同。路径只作为 opaque locator 随模型携带——行标识、显示名、交给消费方的值——除打开时的包含判定外不喂给任何语义 key。

打开流程复用本界面唯一的 `sidebar.workspaces.directoryFlow` 占位者。`WorkspacePickFlow` 新增一个可选的 `adoptPath` 回调以替换 Workspace 采纳逻辑；两个触发点按 Tab 互斥，因此一次占位者挂载仍可服务两者，失败同样落进那个可重试的文件夹错误弹窗。

## Alternatives considered

**按当前 Workspace 列表实时重新判定归属。** 否决：这与设计明确拍板的黏性场景相矛盾，而且会因为注册了一个无关工程就悄悄移动某一行——连带改变从该行开出的会话可写的范围。

**照会话树那样在空时隐藏 Ungrouped 桶，改在面板中央给一个空态按钮。** 否决：入口应当挂在持有这些记录的那一行上，面板正文里再放一个行动号召只是重复。

**为运行记录触发点再渲染一次 directory-flow 洞。** 否决：该洞是 `single` 类型且其占位者无条件渲染，第二个渲染点会把选取交互挂载两次。

**给运行记录行一个默认点击去新建会话。** 否决：这个列表用于回溯与挑选。把行做成任务起点，等于替一套仍在设计中的操作集提前定死。

## Consequences

浏览器持久化状态新增 `openedRunRecords` 与 `runGroupExpansion`；由于 rehydrate 会整体替换 state，persist key 从 `dsh.workspace.view.v5` 移到 `v6`，分组与排序偏好会被重置一次。

在发现层的按需 recognizer 扫盘落地前，工程分节渲染为空——树、归属规则和行都已为它准备好，下游也没有任何东西以路径为 key。归属判定按路径精确比较，因此在大小写不敏感的文件系统上，仅大小写不同的路径会落入桶而不是其工程分节。

native 选取后端的对话框标题仍是 `Select Workspace Directory`，在打开运行记录这条路径上是错的。修正意味着让 directory-flow 接缝携带 owner 指定的用途，波及 Service Definition 与两个后端；这留作后续，不把本次改动扩大。

## Testing

包内 GUI 测试覆盖 Tab 改名、常驻渲染的桶及其独占的 `＋`、把选中目录打开进包含它的工程分节与打开进桶、重复打开的去重、经保留边界确认框的移除、按名称／路径的过滤、Workspace 注销后的回落，以及折叠回到会话的重置。推导单元测试覆盖后代路径判定、两种列出顺序下的最内层 Workspace 归属、分节顺序、折叠行为、黏性归属，以及过滤视图对桶的豁免。构建版 Web 回放快照带上了改名后的 tab。
